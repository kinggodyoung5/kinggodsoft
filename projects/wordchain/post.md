# 개발 후기

## 만든 이유

친구들과 끝말잇기를 할 때마다 단어 유효성(진짜 단어 맞는지) 시비가 붙는 게 귀찮아서, 표준국어대사전 기반으로 실제 검증까지 해주는 웹 버전을 만들었습니다. 혼자서도 연습할 수 있게 봇과 겨루는 싱글 모드도 같이 넣었습니다.

## 어떻게 만들었나

- 빌드 도구 없이 순수 HTML/CSS/JS(ES 모듈)로 구성
- **싱글 모드**: 봇과 1대1 대결, 난이도 5단계(아주 쉬움 500개 / 쉬움 700개 / 보통 1,500개 / 어려움 2,500개 / 매우 어려움 18만여 개 전체 사전)로 봇이 꺼내는 단어 풀과 제한시간이 다르게 설정됩니다(보통 30초, 어려움·매우 어려움 20초, 아주 쉬움·쉬움은 제한 없음). 다섯 단계 모두 같은 실제 사용빈도 순위표에서 상위 N개를 자른 것이라 서로 포함 관계입니다. 쉬운 난이도는 사용빈도 상위 단어만 써서 사람이 이길 수 있게 조정했습니다.
- **대결 모드**: Firebase Realtime Database로 여러 명이 실시간 동시 접속 (완전 무료 Spark 요금제로 충분)
- 단어 검증: 표준국어대사전 기반 명사 약 18만 개, 두음법칙(ㄴ/ㄹ 어두 변형)까지 규칙 기반으로 처리
- 비속어 필터 포함

## 배운 점 / 다음에 할 일

- Firebase 설정을 "중앙화(저장소 공용 프로젝트) + 분산화(브라우저 localStorage에 개인 설정 저장)" 둘 다 지원하게 만들어서, 저장소를 안 건드리고도 각자 자기 Firebase 프로젝트로 테스트할 수 있게 했습니다.
- 대결 모드는 클라이언트가 직접 DB에 쓰는 구조라 완벽한 부정행위 방지는 안 되지만, 캐주얼한 친목 게임 용도로는 충분하다고 판단했습니다.
- 다음에는 오래된 방(room) 데이터 자동 정리 기능을 추가하고 싶습니다.
- 난이도를 5단계로 나누면서 제한시간을 `값 ?? 20000`처럼 기본값과 합치는 코드를 썼는데, "제한시간 없음"을 나타내려던 `null`이 `??` 연산자에서 그대로 걸러져 항상 20초가 적용되는 버그가 있었습니다. `null`도 "값이 있는" 것으로 취급되는 `??`의 특성 때문이라, `hasOwnProperty` 체크로 명시적으로 구분하도록 고쳤습니다.
