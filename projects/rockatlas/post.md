# 개발 후기

## 만든 이유

록 밴드를 장르나 분위기 기준으로 탐색할 수 있는 곳이 마땅치 않아서 직접 만들었습니다. 단순히 밴드 목록을 나열하는 게 아니라, "지금 듣는 밴드에서 조금 더 무겁게/몽환적으로/실험적으로" 같은 방향으로 다음 밴드를 골라주는 탐색 경험을 목표로 했습니다.

## 어떻게 만들었나

- React + TypeScript로 만든 정적 사이트, GitHub Pages로 배포 (`kinggodyoung5.github.io/rockatlas`).
- 밴드 데이터(대표곡, 멤버, 이미지, Wikidata·MusicBrainz 식별자 등)는 `catalog.json` 하나에 모아두고, 13개 상위 장르·140여 개 세부 장르·24개 분위기로 구성된 자체 taxonomy 체계로 분류합니다.
- 개발 지식이 없어도 밴드를 추가·검수할 수 있도록 로컬 전용 관리자 콘솔("Studio")을 별도로 만들었습니다. 외부 검색(Wikidata/MusicBrainz/YouTube/Wikimedia Commons)을 자동으로 대조해서 신뢰도 높은 데이터만 공개로 전환하는 검수 파이프라인이 핵심입니다.
- "히치하이킹" 추천 기능이 가장 공들인 부분입니다. 밴드마다 방향(더 무겁게/더 빠르게/더 웅장하게 등 9종)을 계산해서, 실제로 음악적 연속성이 있는 후보만 최대 4개 방향으로 노출합니다.
- Vitest로 회귀 테스트(70개+)를 유지하면서 기능을 계속 얹었습니다.

## 배운 점 / 다음에 할 일

데이터 신뢰성을 지키는 게 기능을 늘리는 것보다 훨씬 오래 걸린다는 걸 체감했습니다. 자동화(Gemini 인테이크, 외부 API 대조)와 사람의 최종 검수를 분리해두니 오정보가 훨씬 줄었습니다. 앞으로는 카탈로그 규모가 커질수록 필요한 백엔드 검색·백업 체계를 더 다듬을 계획입니다.

전체 코드와 작업 이력은 별도 저장소(`kinggodyoung5/rockatlas`)에서 관리하고 있습니다. 위의 "도구/사이트 바로가기" 버튼을 누르면 실제 배포된 사이트로 바로 이동합니다.
